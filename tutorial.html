Guia de Configuração Maestro

Este guia detalha como configurar o ecossistema Firebase + Google Cloud para seus WebApps baseados no framework 4U.IA.BR.

1. Firebase (Autenticação)

1

Crie o Projeto no Firebase

Acesse o Console do Firebase, crie um projeto e adicione uma "Web App".

2

Ative o Google Login

Vá em Authentication > Sign-in method e ative o provider "Google".

3

Domínios Autorizados (CRÍTICO)

Em Authentication > Settings > Authorized domains, adicione seu domínio de produção (ex: 4u.ia.br).

2. Google Cloud (OAuth 2.0)

Aqui é onde a maioria dos erros acontece. Você precisa de dois tipos de autorização no Google Cloud Console.

A. O Client do Firebase (Obrigatório para Login)

Procure o Client ID que o Firebase criou automaticamente (geralmente chama-se Web client (auto created by Google Service)).

Atenção: Você DEVE adicionar a URL de callback do Firebase nos "URIs de redirecionamento autorizados" deste client:
https://PROJETO-ID.firebaseapp.com/__/auth/handler

B. O Client Manual (Para Calendário/Drive/IA)

Crie um novo **OAuth client ID** do tipo **Web application**.

Configuração:

  • JavaScript Origins: https://4u.ia.br
  • Redirect URIs: https://4u.ia.br/app/NOME-DO-APP/api/oauth_callback.php

3. Chaves de Configuração

No seu arquivo api/config.php, a estrutura das chaves Google deve ser:

define('GOOGLE_CLIENT_ID', 'SUA-CHAVE.apps.googleusercontent.com');
define('GOOGLE_CLIENT_SECRET', 'SEU-SECRET');
define('GOOGLE_REDIRECT_URI', 'https://4u.ia.br/app/keepai/api/oauth_callback.php');

4. Checklist de Erros Comuns

❌ Erro 400: redirect_uri_mismatch

Causa: A URL no console do Google não é 100% igual à do código (falta um 's' no https, falta uma barra, ou o domínio está errado).

Solução: Clique em "Detalhes do erro" na tela do Google e copie a URL exata que ele está pedindo.

❌ Opcache / Cache de Servidor

Causa: Você editou o config.php mas o site continua dando erro.

Solução: Alguns servidores guardam o PHP na memória. Tente renomear o arquivo ou limpar o cache no painel da hospedagem.

Master Configuration Guide

This guide details how to configure the Firebase + Google Cloud ecosystem for your WebApps built on the 4U.IA.BR framework.

1. Firebase (Authentication)

1

Create Firebase Project

Open the Firebase Console, create a project, and add a "Web App".

2

Enable Google Sign-in

Go to Authentication > Sign-in method and enable the "Google" provider.

3

Authorized Domains (CRITICAL)

Under Authentication > Settings > Authorized domains, add your production domain (e.g. 4u.ia.br).

2. Google Cloud (OAuth 2.0)

This is where most setup errors occur. You need two types of authorization in the Google Cloud Console.

A. The Firebase Client (Required for Login)

Locate the Client ID automatically created by Firebase (usually named Web client (auto created by Google Service)).

Warning: You MUST add the Firebase callback URL into the "Authorized redirect URIs" of this client:
https://PROJECT-ID.firebaseapp.com/__/auth/handler

B. The Manual Client (For Calendar / Drive / AI)

Create a new **OAuth client ID** of type **Web application**.

Configuration:

  • JavaScript Origins: https://4u.ia.br
  • Redirect URIs: https://4u.ia.br/app/APP-NAME/api/oauth_callback.php

3. Configuration Keys

In your api/config.php file, the Google keys structure must be:

define('GOOGLE_CLIENT_ID', 'YOUR-KEY.apps.googleusercontent.com');
define('GOOGLE_CLIENT_SECRET', 'YOUR-SECRET');
define('GOOGLE_REDIRECT_URI', 'https://4u.ia.br/app/keepai/api/oauth_callback.php');

4. Common Errors Checklist

❌ Error 400: redirect_uri_mismatch

Cause: The URL in the Google console does not 100% match the code (missing 's' in https, missing slash, or wrong domain).

Solution: Click "Error details" on the Google error screen and copy the exact URL it is requesting.

❌ Opcache / Server Cache

Cause: You updated config.php but the server keeps serving the cached PHP script.

Solution: Some hosting servers keep PHP in memory. Try clearing the cache in the hosting control panel.
